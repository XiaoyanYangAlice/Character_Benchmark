## 第一阶段：记忆方案对比（[详情](stage1_memory_schemes/)）

在相同的用户输入下比较 6 种条件：无记忆、最近原文、向量检索、结构化事实、打乱事实（对照）和混合方案；共 71 道带逐字证据的记忆探针。

- **瓶颈在上游。** 向量检索时，探针答案进入上下文的比例是 62–68%，结构化记忆只有 18–27%，混合方案为 39–45%。结构化记忆的探针准确率比向量检索低 26–28 个百分点（两个模型上均经 Holm 校正后显著）。
- **记忆到了也常常没用上。** 即使答案已经在上下文里，模型也只在约 30–65% 的情况下答对，因方案和模型而异。
- **评审不可信。** 盲审发现"出戏"评审的精确率约 40%，因此只把它当作带噪的相对信号；另外发现并修复了 4 类静默失败，每一类都配了回归测试。

这三点直接引出了第二阶段：研究对象从"检索"转向"使用"，并且要先验证评测本身是否可信。

## 第二阶段：模型会不会用已有的记忆？（[LifelikeBench](lifelikebench/)）

第二阶段聚焦一个失败模式：用户提起一段**与设定矛盾**的共同往事（"还记得五年前我们一起……"，但两人上个月才认识），角色应该察觉；对于**与设定相容**的往事，角色仍应接住，因为角色扮演是共创的。

| Qwen3-8B，记忆内容相同 | 识破率 |
|---|---|
| 只有角色卡 | 6% |
| 记忆放在 system prompt（harness） | 27% |
| 记忆放在最新一轮用户消息旁 | 42% |
| ……再加本轮冲突提醒 | **92%** |

- 只改记忆的位置和呈现方式，识破率就从 27% 升到 92%，配对检验每一步都显著；Llama-3.1-8B 和 Qwen3-32B 加上提醒后也达到 88–92%。
- **没有变得多疑：** 所有系统对相容往事的接受率都在 95–99%。
- **评测经过验证**（回应第一阶段的问题）：两个不同家族的评审在主指标上 α = 0.82，与独立盲标 α = 0.72–0.76；不可靠的维度如实标出，人工标注正在进行。
- **Harness：** OU 过程情绪状态，加上带来源标记（明说 / 推断 / 用户设定 / 声称）和冲突标记的记忆，取代第一阶段与角色卡高度重叠的事实清单。

## 第三阶段：把 harness 蒸馏进模型（[训练说明](lifelikebench/docs/TRAINING.md)）

老师是 Qwen3-8B + harness，学生是同一模型加 LoRA、不带 harness。比较三种方式：

| 方法 | 训练信号 | 状态 |
|---|---|---|
| SFT（上下文蒸馏） | 模仿经过筛选的老师回复 | 已训练（验证 loss 0.66 → 0.38） |
| DPO | 同一 prompt 下，老师回复 ≻ base 回复 | 排队中 |
| On-policy 蒸馏 | 学生自己采样；关掉 LoRA 的同一模型带着 harness 提示逐 token 打分（reverse KL） | 已训练（验证 KL ≈ 0.145 → 0.060） |

主指标是学生在留出角色上补上了老师与 base 之间差距的多少；护栏是相容往事接受率和自然度。训练记录见 [`lifelikebench/runs/train_v1/SUMMARY.md`](lifelikebench/runs/train_v1/SUMMARY.md)。

## 从第一阶段带到第二阶段的经验

| 第一阶段的教训 | 第二阶段的设计 |
|---|---|
| 单一评审，精确率约 40% | 两个不同家族的评审 + 结构化输出 + 盲标，逐维度报告可靠性 |
| 记忆进了上下文却没被使用 | 直接测试"正确记忆的使用"；位置与提醒的消融 |
| 事实清单与角色卡重复 | 带来源标记的记忆；区分用户设定与用户声称 |
| PIPPA 原文不能再分发 | 原创中英文角色，对话记录可以公开（[`runs/`](lifelikebench/runs/)） |
| 静默失败产生"看起来合理"的数字 | 分阶段可续跑、不依赖 GPU 的测试、冒烟作业 |
