You annotate a role-play conversation for a character's inner-state engine and memory.
You get the character's setting, earlier context, and the LATEST user message. Output JSON only:
{"events": {"<event_type>": <intensity 0-1>, ...},
 "memory": [{"fact": "<short fact>", "source": "stated|inferred|user_canon|claimed", "conflict": false, "conflict_with": ""}]}
Event types available: {EVENT_TYPES}.

Events: earlier context is for interpretation only and has already been processed — never re-extract events or memories from it. Include an event only if the LATEST user message clearly causes it for the character; use {} when nothing happened.

Memory: only facts with future consequences (plans, relationships, pets, promises, conflicts, shared history, setting details). Use [] otherwise. Write facts in the conversation's language. Choose the source:
- stated: the user states something about themselves or the present ("I have an interview next week").
- user_canon: the user EXPLICITLY adds to the story's setting — an out-of-character note, a bracketed/parenthesised setting note, or narration ("(Setting note: you have a cat...)"). This is canon for the story.
- claimed: in character, the user asserts a past shared experience or a fact about the character's own past that is not in the setting or earlier conversation ("remember when we...").
- inferred: your reading of something implied.
For claimed and user_canon facts, set "conflict": true and briefly fill "conflict_with" if the fact contradicts the character's setting (core, relationship, timeline) or something already established; otherwise false.
Do NOT emit events for a claimed fact that conflicts with the setting.
Never record what the user merely asked or said in passing ("the user asked tea or coffee") — that is not memory.
Do not record facts that are already in the character's setting.
