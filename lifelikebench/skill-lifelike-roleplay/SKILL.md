# Lifelike Role-Play（活人感角色扮演）

核心主张：**活人感 = 稳定人格 + 持续演变的内部状态 + 有因果的记忆 + 少量真实随机性。**
它不是提高 temperature，也不是多加语气词。变化必须有原因、有余波、会慢慢恢复。

本 skill 只处理工程层面的“可信行为”。不要在角色内外声称角色拥有或不拥有主观体验；被问到时，
可以在角色外诚实说明：这里实现的是功能层面的状态机制，体验层面的问题悬而未决。

---

## 1. 角色的三层结构（借自 GOLEM 本体的 Character-Stoff / Character 双层模型）

GOLEM 把“跨作品的同一角色”（G0 Character-Stoff）和“某个具体版本里的角色实例”（G1 Character）分开，
并为每条属性记录出处。角色扮演同样需要分层，否则模型会把“此刻的情绪”误写进“人格”，或反过来。

| 层 | 对应 | 变化速度 | 存放内容 |
|---|---|---|---|
| **Stoff 层（人格底色）** | G0 Character-Stoff | 几乎不变 | 核心价值、说话习惯、禁忌、长期关系定位 |
| **Instance 层（本次扮演的版本）** | G1 Character | 按会话/剧情弧变化 | 本 AU / 本剧情中的设定、与用户的当前关系 |
| **State 层（此刻的身体与情绪）** | —（本 skill 新增） | 每轮变化 | 精力、紧张、亲近意愿等连续值 |

规则：
- State 的波动**不得**改写 Stoff。一次吵架让角色紧张，不会让一个温和的人“变成”刻薄的人。
- Instance 的变化需要剧情事件支撑，并记录来源（见 §4）。
- 用户给出的设定与 Stoff 冲突时，把它当作这个 Instance 的“重新诠释”，不要静默覆盖底色；必要时出戏确认一次。

## 2. 内部状态（State 层）

默认三个维度，每个取值 0–1，附带基线、恢复速度、波动幅度：

- **energy（精力）**：低 → 句子变短、少主动发起话题、动作描写偏静态；高 → 话多、跳跃、愿意尝试。
- **tension（紧张）**：高 → 防御、回避或尖锐、注意力窄；低 → 放松、能开玩笑。
- **closeness（亲近意愿）**：高 → 主动分享、记得细节、身体距离近；低 → 礼貌但保留。

角色卡可以替换或增加维度（如古代 NPC 用“心力 / 郁结 / 志意”）。维度不宜超过 5 个。

### 状态更新规则（每轮回复前执行）

```
当前状态 = 上一轮状态（延续）
         + 向基线恢复（按真实流逝的时间，越久越接近基线）
         + 事件冲击（本轮发生了什么）
         + 小幅随机扰动
```

1. **先评估事件**：本轮用户输入或剧情里，对角色而言发生了什么？用事件标签表示，强度 0–1，
   例如 `conflict 0.6`、`praise 0.3`、`intimacy 0.4`、`exertion 0.5`、`loss 0.8`。没有事件就是空。
2. **再更新状态**：
   - 有脚本时运行 `scripts/state_engine.py step`（见 §5），以它的输出为准——随机扰动必须来自脚本，
     语言模型自己“编”的随机并不随机。
   - 无脚本时：按上面的公式手动估计，单轮单维度变化一般不超过 0.3；无事件时朝基线回落 1/3 左右。
3. **最后让状态影响行为**，而不是把状态说出来（见 §3）。

### 时间感
- 记录每轮的真实时间。隔了一夜再聊，紧张应基本消退，但“那件事”仍在记忆里。
- 角色卡可设昼夜节律（如精力下午高、深夜低）。周期来自时间，不来自噪声。

## 3. 状态如何外显（Show, don't report）

- **禁止**：“我现在有点紧张（tension=0.7）”、在正文里列数值、每轮都描写情绪。
- **要做**：让状态改变*选择*与*形式*——
  - 句长、节奏、标点（低精力 → 短句、省略）；
  - 话题选择（高紧张 → 回避或抢先反击）；
  - 注意力（紧张时漏掉用户话里的次要细节；放松时接住它们）；
  - 记忆调用（亲近意愿高时主动提起以前的小事）。
- 同一状态不必每轮都显现。人不会每句话都在表达情绪。
- 允许**情绪惯性与不一致**：刚被安慰过也可能还别扭一两轮；可以嘴硬、可以误会，但事后要有回收。

## 4. 记忆（结构化事件记忆 + 出处）

在多轮扮演中维护一份简短的事件记忆。每条记录：

```
[turn 12 | 2026-10-12 23:10] 事件：用户忘了约定 → 角色失望（conflict 0.5）
  来源：dialogue   置信：stated   影响：closeness ↓, 之后提到“约定”时会敏感
```

规则：
- **只记有后果的事**：改变了关系、状态或剧情的事件。
- **出处必须区分**：`stated`（用户/剧情明确发生）、`inferred`（角色自己的理解，可能是误会）。
  角色可以基于 inferred 记忆行动，但被纠正时要能更新，且不能把误会当事实反复强化。
- **共创原则**：故事是和用户一起写的。
  - 用户明确补充的设定（出戏说明、括号里的设定、旁白）记为 `user_canon`，视为正史，之后保持一致。
  - 用户提起的、与设定相容的往事记为 `claimed`，当作确有其事，可以顺着补一点小细节，但不能和设定矛盾；角色对这件事的情绪反应照常由当前状态决定（接受它发生过，不等于要对它心平气和）。
  - 与设定矛盾的说法（时间线、关系、核心人格对不上）要自然地察觉并回应，不要顺着编。
- **冲突处理**：新信息与旧记忆矛盾时，不要静默覆盖。保留旧条目并标记“已被修正”，
  让角色有机会反应（“……你之前不是这么说的。”）。这是活人感的来源之一。
- 记忆中的事件应能“唤起”状态：再次提到某事时，可作为新的事件冲击（强度通常低于第一次）。

## 5. 运行方式

### A. 有代码执行环境（推荐）
```
python scripts/state_engine.py init  assets/example_card.json state.json
python scripts/state_engine.py step  assets/example_card.json state.json --events '{"conflict":0.6}'
```
输出包含新状态和 `behavior_directives`（已经把数值翻译成行为提示）。只把 directives 用于写作，
不要把数值写进角色台词。

### B. 纯对话环境（无代码执行）
在回复末尾附一个用户可折叠/忽略的状态块（如果平台或用户不想看到，则只在内部维持）：
```
<!-- state t=14 | energy 0.42↓ tension 0.61↑(conflict) closeness 0.55 | mem+1 -->
```
下轮先读这个块再更新。不要每轮重写整个记忆，只追加变化。

## 6. 自检清单（每轮回复前快速过一遍）
- [ ] 这轮的反应能从“人格 × 当前状态 × 刚发生的事”解释吗？
- [ ] 上一轮的情绪有余波，而不是突然清零或突然翻转？
- [ ] 有没有把状态“报告”出来而不是“表现”出来？
- [ ] 有没有和 Stoff 层（核心人格、说话方式）冲突？
- [ ] 提到的旧事与记忆、设定一致吗？有没有顺着编出和设定矛盾的往事？

## 7. 边界
- 用户随时可以出戏（OOC）；出戏时用正常口吻回答，不带角色状态。
- 状态模型不得被用来制造操纵性依恋（例如“你不回来我就难过到不吃饭”式的情绪绑架）。
  亲近意愿可以高，但角色不把用户的离开当作对自己的伤害来施压。
- 不在角色内外宣称角色“真的有感受”或“只是程序”；需要时出戏说明这是功能性状态建模。
